\section*{Supplementary Note 1: Co-authorship network connectivity before and after mining}\label{snote:network}

% Sources: outputs/seed_vs_full_network_comparison.csv and outputs/coauthorship_network_summary.json (not the .prev copy).
Our network mining process grows outward from a known co-authorship network similar to a snowball sampling process.
As a result, the network becomes increasingly connected and concentrated in a single large component.
To evaluate network connectivity, we compare the co-authorship network created from the seed pairs alone to the co-authorship network created from the seed and mined pairs together.
In each network, researchers are nodes and an undirected edge joins two researchers who share an RS-Graph article.
Single-author articles add no edges, so we exclude researchers without any co-authorship edge, which removes 3,834 researchers from the seed-only network and 3,132 from the seed and mined network.
The largest connected component holds 84.9\% of researchers in the seed-only network (354,036 of 417,082) and 93.6\% in the seed and mined network (590,147 of 630,651).
Over the same change, the number of connected components falls from 14,145 to 9,387, and the second-largest component in the seed and mined network has only 49 researchers.
We expect this increase by construction, because we find every mined pair through a researcher who already authored an article in RS-Graph.

\section*{Supplementary Note 2: Out-of-domain repository sample}\label{snote:ood}

% Sources: pool size from sci-soft-models binary_article_repo_em full-ood-sample.parquet (394,707 rows); 93 test-positive repositories also in the pool (2026-10-28 check). Query date and criteria from Eva (2026-10-29), not yet pinned to a file.
Negative strategies 2 and 3 pair seed articles with repositories from an out-of-domain sample of GitHub.
Compiling a random sample of GitHub repositories through the public API is difficult~\cite{kalliamvakou2016promises}, so GitHub staff provided the sample by querying GitHub's internal database of repository information for public repositories created before July 2025.
The sample is meant to represent the non-research repositories the ARMM may meet during mining, such as homework assignments, course materials, and side projects.
It holds 394,707 repositories, which we split into disjoint pools for the training and test sets.
We did not filter the sample against the seed pairs, and 93 repositories from positive test pairs also appear in it.
The out-of-domain repositories used as negatives are included in the ARMM training dataset (Code availability), and the full sample is available on request.
We thank GitHub staff for providing it.

\section*{Supplementary Note 3: ARMM input format}\label{snote:armminput}

% Source: sci-soft-models binary_article_repo_em/constants.py (OPTIMIZED_MODEL_STR_INPUT_TEMPLATE, truncation lengths, TRUNC_ELEMENT); main.py _prepare_input and training.py use the same template, and missing values become the string "None" in both.
We pass each candidate article-repository pair to the ARMM as a single XML string, built from the template below by replacing each placeholder in braces with the pair's value.
The same template builds the training, evaluation, and mining inputs.
We truncate abstracts at 3,000 characters and READMEs at 6,000 characters, and we append \texttt{<TRUNC/>} to any text we truncate.
We write a missing value as the string \texttt{None}.

\section*{Supplementary Note 4: ARMM configuration and training}\label{snote:armmconfig}

% Sources: sci-soft-models binary_article_repo_em: final-model-training-data-optimized/train-script-final-article-repo-em.py (TrainingArguments) and results.json (thresholds); data/files/ablation/ablation-training-results.csv and data/files/experiments/exp-training-results.csv (model selection). Optimizer and schedule are not set in the script, so they are the Transformers defaults.
Due to the randomness of synthetic negative creation, there is a chance that a negative strategy reproduces a positive example.
As such, after all negative generation, we deduplicate all pairs, keeping the positive pair wherever a synthetic negative duplicates a real seed pair.

We fine-tuned the final ARMM with the Hugging Face Transformers \texttt{Trainer} using the settings below.

\begin{center}
\footnotesize
\begin{tabular}{@{}ll@{}}
\toprule
Setting & Value \\
\midrule
Base model & \texttt{gte-multilingual-base} \\
Input features & 18 (Supplementary Note 3) \\
Epochs & 1 \\
Optimizer and learning-rate schedule & Transformers defaults (AdamW) \\
Learning rate & $5\times10^{-5}$ \\
Weight decay & 0.01 \\
Mixed precision & FP16 \\
Gradient checkpointing & Yes \\
Batch size & Found automatically (\texttt{auto\_find\_batch\_size}) \\
Maximum input length & 8,192 tokens \\
Random seed & 12 \\
\botrule
\end{tabular}
\end{center}

We chose the input features and base model with single runs, one per configuration, each fine-tuned for one epoch with the same settings on a subsample of 32,768 positives and evaluated on a separate 39,988-example model-selection set (17,696 match, 22,292 no-match; Supplementary Table~\ref{stab:ablation}).
These runs predate a revision of our train/test split, which now splits positives before generating negatives, so the model-selection set was most likely built with the earlier procedure, which generated negatives before splitting.
The same configuration (\texttt{gte-multilingual-base} with the final 18 features) scored a macro F1 of 0.967 in the base-model run and 0.961 in the ablation run, so single-run differences of about 0.006 are within noise.
We therefore did not select the highest-scoring feature set.
We excluded the six features (author list, contributor list, topic domains, topic fields, document type, and repository file tree) mainly because they need multiple API calls per candidate pair before inference, which would make mining time-intensive, and we dropped the author and contributor lists together so the model could not lean on their overlap (Methods).

On the 120,030-example test set, the candidate confidence thresholds were 0.751 by Youden's J, 0.479 by maximum F1, 0.940 as the lowest threshold with a false positive rate of at most 0.01, and 0.99937 as the lowest threshold with precision of at least 0.999.
We use the last, rounded to 0.9994 (Methods).
